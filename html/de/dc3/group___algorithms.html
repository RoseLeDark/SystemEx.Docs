Detailed Description

A specialized search provider implementing binary-search-based probing.

Provides a set of sorting algorithms that operate on any container implementing IVector<T>.
All algorithms use ISimpleCompare<T> as their comparison strategy.

Provides a standard comparison implementation for values wrapped in Optional<T> where T implements IComparable<T>.

A simple fallback search provider that performs a linear scan over the container and counts how many elements match the given condition.

Provides a Fibonacci‑based search strategy for containers implementing IContainer<T>.

This provider assumes that the underlying TContainer is sorted according to the predicate or comparison logic used. It performs a midpoint probe to locate any matching element and then expands outward to collect all adjacent matches. This makes the provider efficient for clustered or repeated values in sorted sequences.

Important: This search provider is only valid for sorted containers. If the data is not sorted, use a linear search provider instead.

Behavior:

  • Find returns the number of matching elements by probing the midpoint and expanding left/right until non-matching elements are encountered.
  • Where returns all matching elements together with their indices.
  • Matching is determined solely by the provided predicate or ISimpleCompare<T> implementation.
Template Parameters
TElement type stored in the container.
TContainerContainer type implementing IVector<T>. Must provide indexed access and a stable element order.

Fibonacci search is an alternative to binary search that uses decreasing Fibonacci intervals to narrow the search space. It is particularly suited for sorted containers and scenarios where comparison operations are more expensive than index arithmetic.

Template Parameters
TThe element type stored in the container.
TContainerThe container type being searched. Must implement IVector<T>.

Important: This provider does not return an index. It returns the number of matches. The VectorSearch<T, TContainer> system is designed for complex search algorithms that may evaluate multiple matches, patterns, or conditions. It is not a replacement for the traditional Find API.

Purpose: LinearSearchProvider serves as a universal fallback implementation. More advanced providers (binary search, segmented search, pattern matching, domain‑specific logic) should be implemented separately.

The comparison delegates to Optional<T>.CompareTo(Optional<T>), which defines ordering semantics for present and non‑present values.
