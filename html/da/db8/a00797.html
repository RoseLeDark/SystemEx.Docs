enum SystemEx.Utils.CompareResult : sbyte

Specifies the result of a comparison between two values.

This enumeration is used by CompFunc<T> and the generic algorithms in Algorithm to express ordering relations between two operands A and B. It generalizes the usual "less/greater/equal" semantics with additional states for "equal but smaller" and "equal but larger" to support nuanced ordering logic.

Enumerator
Less 

Alias for CompareResult.AIsSmallerB. Indicates that the first operand is strictly smaller than the second.

Greater 

Alias for CompareResult.AIsLargerB. Indicates that the first operand is strictly larger than the second.

EqualLess 

Alias for CompareResult.AIsEqualSmallerB. Indicates that the first operand is equal to the second but considered "smaller" in a secondary ordering dimension.

EqualGreater 

Alias for CompareResult.AIsEqualLargerB. Indicates that the first operand is equal to the second but considered "larger" in a secondary ordering dimension.

AIsLargerB 

The first operand A is strictly larger than the second operand B.

AIsSmallerB 

The first operand A is strictly smaller than the second operand B.

Equal 

The operands A and B are considered equal in the primary ordering dimension.

AIsEqualLargerB 

The operands are equal in the primary dimension, but A is treated as "greater" in a secondary dimension (e.g. tie‑breaking).

AIsEqualSmallerB 

The operands are equal in the primary dimension, but A is treated as "smaller" in a secondary dimension.

Null 

One or both operands are null, or the comparison function cannot produce a meaningful ordering result.

◆ Endian

enum SystemEx.Endian

Specifies the byte order used when converting values to and from raw byte sequences.

Endianness determines how multi‑byte numeric values are represented in memory and serialized into byte arrays. All conversion methods in SystemEx.Utils.Conversion support explicit endianness to ensure deterministic binary layouts across platforms.

The enumeration provides three modes:

  • Endian.LittleEndian — least significant byte first.
  • Endian.BigEndian — most significant byte first.
  • Endian.System — use the native endianness of the current machine as detected by SystemEx.Utils.Conversion.GetEndian.

Note: When Endian.System is specified, conversion methods do not perform byte‑swapping. They serialize values exactly as the CPU represents them in memory. This is typically little‑endian on modern x86/x64 systems.

Enumerator
LittleEndian 

Least significant byte first (little‑endian). This is the native format on most modern architectures including x86 and x64.

BigEndian 

Most significant byte first (big‑endian). Common in network protocols and some older CPU architectures.

System 

Uses the system’s native endianness as detected by SystemEx.Utils.Conversion.GetEndian. This mode ensures that values are serialized exactly as the CPU stores them in memory, without performing any byte‑swapping.

Represents a comparison function for two values of type T .

The function receives two operands a and b and returns a CompareResult describing their ordering relation. This delegate is used throughout Algorithm to implement generic, type‑agnostic algorithms such as sorting, min/max selection, and lexicographical comparison.
